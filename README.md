# graphql_builder

Декларативный билдер GraphQL-запросов для Dart. Пакет собирает дерево полей,
вложенных связей и аргументов, проверяет совместимость описаний и создаёт тело
запроса. Требуется Dart `>=3.8.0 <4.0.0`; Flutter и зависимости времени исполнения
не нужны.

## Подключение

В `pubspec.yaml` каждого приложения добавьте зависимость рядом с остальными
зависимостями, затем выполните `flutter pub get` в каталоге приложения:

```yaml
dependencies:
  graphql_builder:
    path: ../graphql_builder
```

Все публичные типы доступны через один импорт:

```dart
import 'package:graphql_builder/graphql_builder.dart';
```

Единственный запускаемый пример —
[example/graphql_builder_example.dart](example/graphql_builder_example.dart).
Он объявляет корень `employee` и поле `id`, затем собирает запрос одного
сотрудника с фильтром по `id`; результат выводится в stdout без отправки на
сервер.

## Как описать схему

1. Объявите корень `QueryRoot('employee')` и создайте выборку через
   `Node(root)`. Имена корня и полей должны совпадать с GraphQL-схемой.
2. Для поля, которое только выбирается, используйте `Field('name')`. Для
   фильтруемого поля — `ScalarField<int>(name: 'id', operators:
   {FilterOperator.equal})`. Тип значения задаёт встроенный кодек для `bool`,
   `int`, `num`, `String` и `NumericId`. Для дат, nullable и пользовательских
   типов передайте `codec` явно. `ComparableField<T>` поддерживает операторы
   сравнения, `ArgumentField<T>` представляет аргумент без поля ответа.
3. Соберите условия через `Filters` и добавьте их в узел. Без `owner` поле можно
   добавить в любой узел; без `scopes` фильтр можно применить к любому корню или
   связи. Это удобный режим для небольших запросов, но проверка существования
   поля и аргумента остаётся за GraphQL-сервером.
4. Для локальной проверки схемы задайте `owner: root` и `scopes: {root.scope}`.
   Вместо параметров поля можно передать готовый `InputDefinition` с кодеком,
   допустимыми операторами и серверными именами аргументов. `argumentNames`
   переопределяет имя конкретного оператора; сортировка требует `sortArgument`.
5. Если несколько корней выбирают один объект, используйте
   `QueryRoot.withTypeOf('employee', employeesRoot)`. Связи можно объявлять через
   `Relation.betweenRoots`; пагинацию включайте через `PagePagination`.
   Дескрипторы, которые переиспользуются в запросах, сохраняйте в `static final`.

`Filters` принимает обе формы: `add(BooleanFilter(field), true)` и
`add(InFilter(field, [1, 2, 3]))`. Операторы проверяют тип поля; значения проверяются
кодеком при связывании фильтра. Уже связанному фильтру нельзя передать ещё одно
значение. У `NullFilter` и `NotNullFilter` значения нет; им нужен nullable-кодек.

## Поведение билдера

- `Query.add`, `Node.addNode`, `Node.addFilters` и `freeze()` сохраняют снимок
  текущего состояния. Последующие изменения исходного узла или фильтров не
  меняют уже добавленную выборку. `addAll(selection)` переносит поля, аргументы
  и пагинацию снимка.
- Повторные поля объединяются рекурсивно. Разные аргументы у одного имени
  результата вызывают ошибку; для независимых выборок задайте разные aliases.
  Конфликтующее добавление отклоняется целиком.
- Связь задаётся в конструкторе дочернего узла либо через `addNode(child, via:
  relation)`. Билдер не угадывает, какую связь использовать. При добавлении
  проверяются типы и идентичность родителя, дочернего объекта и полей.
- Для фильтров с явными `scopes` проверяется область применения. Одинаковые
  аргументы объединяются с пересечением разрешённых областей; фильтр без
  `scopes` не ограничивает это пересечение. Конфликтующие значения отклоняются.
- Фильтры компилируются в **плоские аргументы**. По умолчанию используются суффиксы
  `__Is`, `__Gt`, `__Gte`, `__Lt`, `__Lte`, `__In`, `__NotIn`, `__ILike`,
  `__Null`, `__NotNull`; равенство использует имя без суффикса. Это соглашение
  конкретного API, а не стандарт фильтрации GraphQL. Описывайте только операторы,
  действительно поддерживаемые сервером, и меняйте имена через `argumentNames`.
- `Page(index: 0, size: 50)` использует индекс с нуля. `PagePagination` задаёт
  серверные имена аргументов и смещение `firstPage`. Если пагинация не объявлена
  для корня или связи, её использование отклоняется.
- `SortBy` передаёт `true` для `ascending` и `false` для `descending` под явно
  заданным `sortArgument`. Для другого серверного соглашения потребуется
  расширение пакета.
- `ValueCodecs` поддерживает boolean, числа, целые, строки, числовые ID и даты
  с явно переданной функцией форматирования. `nullable()` добавляет поддержку
  `null`, в том числе внутри списков. `NumericId` сохраняет длинные цифровые ID
  без потери точности и выводит их без кавычек. Для обычного GraphQL ID со
  строковыми значениями используйте строковый кодек. `EnumValue` выводит
  проверенное имя enum без кавычек. Пользовательский `ValueCodec` может возвращать
  поддерживаемые литералы, списки и объекты.

`Query.build()` возвращает `GraphRequest`. У него есть `query`, `operationName`,
`variables`, `toJson()` и `toJsonString()`. Необязательное имя операции задаётся
через `Query(name: ...)` и попадает в JSON только для именованного запроса.

### HTTP и ответы

В обоих приложениях основной Dio настроен на form-urlencoded и принимает все
HTTP-статусы через `validateStatus`; в ERP дополнительно задан
`ResponseType.plain`. Если адаптер отправляет `request.toJson()`, ему нужно
переопределить `contentType` на JSON для конкретного запроса. Не меняйте глобальные
настройки общего Dio ради GraphQL. Используйте JSON-ответ для этого запроса либо
явно декодируйте строковый ответ. Проверяйте HTTP-статус и GraphQL `errors`, включая
ответы HTTP 200; способ обработки частичных `data` определяет приложение.

Пакет не отправляет запросы, не управляет токенами и не создаёт отдельный Dio.
Подключение в приложения и перенос их существующих запросов выполняются отдельно.


## Ограничения и статус

- Сейчас генерируются операции `query` с inline-литералами и пустым неизменяемым
  `variables`. Компиляции переменных, mutations, subscriptions, directives и
  fragments нет. Переиспользование реализовано через снимки `Selection`.
- Синтаксические имена, литералы, типы значений и совместимость локальных
  дескрипторов проверяются. Пакет не загружает SDL/introspection и не проверяет
  существование полей или аргументов в серверной схеме.
- JSON-тело можно проверить локально; совместимость с конкретным сервером
  подтверждается интеграционными запросами приложения.
- Пакет приватный (`publish_to: none`). Лицензия пока не выбрана; публикация и
  условия распространения требуют отдельного решения владельца.
